프로젝트 개요

DB손해보험 디자인 리뉴얼 프로젝트로, 기존 적응형(Adaptive) 구조를 반응형(Responsive) 구조로 전환하는 작업을 담당했습니다.

단순 전환이 아닌, 기존 적응형 페이지는 계속 운영해야 하는 상황이었기 때문에 전체를 한 번에 바꾸는 것이 아닌 순차적 전환 방식으로 진행되었습니다. 이로 인해 적응형과 반응형 구조가 동시에 운영되는 환경에서, 전환 대상 페이지에 한해 기존 모바일/PC 분리 코드를 통합하는 방식으로 구조를 설계했습니다.

핵심 도전 과제

• 적응형·반응형 구조 동시 운영
기존 적응형 코드는 그대로 유지하면서, 반응형으로 전환되는 페이지들만 선별적으로 모바일/PC 코드를 통합해야 했습니다. 파일 구조 설계와 코드 정리에 많은 시행착오를 거쳐, 최종적으로 두 구조를 안정적으로 병행 운영할 수 있는 체계를 구축했습니다.

• 공통 컴포넌트 분리 및 파일 구조 재정비
기존 코드는 공통으로 사용 가능한 요소들이 각 페이지에 개별적으로 포함되어 있어 유지보수가 어려운 구조였습니다. 공통 컴포넌트를 분리하고 공통 파일 구조로 재정리하여 유지보수성을 크게 개선했습니다.

• 신규 보험 가이드 페이지 제작
리뉴얼과 함께 신규 보험 가이드 페이지를 기획·제작하여, SEO / AEO / GEO 관점에서 검색 노출 및 인용률 향상을 도모했습니다. 특히 보험 가이드 메뉴 내 driver-01 페이지에서 AI를 이용하여 스키마를 작성하고 연결했으며, 메타 태그·canonical·Open Graph와 함께 적용해 검색 친화적인 콘텐츠 구조를 구축했습니다.

AI(Claude)를 활용한 설계 · 리팩터링 프로세스

이 프로젝트에서는 AI(Claude)를 단순 코드 자동완성 도구가 아닌 설계 파트너로 활용했습니다. 기존 적응형 구조를 반응형으로 재설계하는 과정에서, 한 페이지를 개선한 방식을 마크다운 규칙 문서로 정의해 AI에게 학습시키고, 이를 기준으로 나머지 페이지의 구조 오류까지 자동으로 검출·QA하는 "1개 수정 → 전체 확산" 워크플로우를 설계했습니다.

현황 진단 & 파일 구조 재설계

기존 적응형 코드(모바일/PC 분리, 페이지마다 중복된 공통 요소)를 AI와 함께 분석하여 문제점을 진단하고, 반응형 전환에 맞는 공통 컴포넌트 분리 · 파일 구조 개편안을 도출했습니다. 사람이 놓치기 쉬운 중복·불일치 지점을 AI가 교차 점검했습니다.

기존 설계 진단 · 구조 개편

마크다운 규칙 문서화 → AI 컨텍스트 학습

한 페이지를 리팩터링하며 확정한 마크업 규칙·네이밍·반응형 분기 기준을 마크다운 구조 문서로 작성했습니다. 이 문서를 AI가 학습하는 기준(컨텍스트)으로 삼아, 이후 다른 페이지들도 동일한 규칙으로 일관되게 정리되도록 했습니다. 즉 표준 1개를 만들면 나머지에 그대로 확산되는 구조입니다.

마크다운 규칙 정의 · 컨텍스트 주입

크로스 페이지 오류 자동 검출

학습된 규칙을 기준으로 AI가 나머지 페이지들의 구조 오류를 스스로 검출하도록 했습니다. 닫히지 않은 태그, 헤딩 계층(h1~h3) 붕괴, 규칙에서 벗어난 클래스 네이밍, 반응형 분기 누락 등 사람이 페이지마다 일일이 찾기 어려운 문제를 일괄로 잡아냈습니다.

일관성 검사 · 오류 일괄 검출

AI QA · 검증

수정 결과에 대해 AI QA를 진행했습니다. 시맨틱 마크업 적정성, 접근성(대체 텍스트·헤딩 순서), SEO/스키마 유효성, 반응형 레이아웃 깨짐 여부를 점검하고, 발견된 이슈를 다시 수정 → 재검증하는 반복 루프로 품질을 끌어올렸습니다.

시맨틱 · 접근성 · SEO QA
1페이지 개선 → 마크다운 규칙화 → AI 학습 → 전체 페이지 오류 검출 → AI QA · 재검증

아래는 실제로 AI에게 학습 기준으로 제공한 마크다운 규칙 문서를 일반화한 예시입니다. 이 문서 하나로 여러 페이지의 구조를 동일한 기준으로 정렬하고 검증할 수 있었습니다.

AI 학습용 구조 규칙 문서 (예시)

페이지별 편차를 없애기 위해 마크업·네이밍·반응형 기준을 마크다운으로 명문화하고, AI QA 체크리스트를 함께 정의했습니다.

# 반응형 전환 페이지 작성 규칙

## 1. 파일 구조
- 공통 요소(header/footer/form)는 `/common/*.php` 로 분리
- 페이지 고유 마크업만 개별 파일에 유지

## 2. 마크업 규칙
- 문서당 h1은 1개, 섹션 제목은 h2 → h3 순서 유지
- 이미지에는 의미 있는 alt 필수
- 모바일/PC 분리 코드 금지 → 반응형 단일 마크업 + CSS 분기

## 3. 네이밍
- 블록: `perCont`, 요소: `faqItem`, 상태: `is-active`

## 4. AI QA 체크리스트 (자동 점검 항목)
- [ ] 닫히지 않은 태그 / 잘못된 중첩
- [ ] 헤딩 계층(h1~h3) 붕괴 여부
- [ ] 규칙 외 클래스 네이밍
- [ ] 반응형 분기 누락 (min/max-width)
- [ ] 스키마(JSON-LD) 유효성 · canonical 존재
1 → N 표준 1개 정의로 여러 페이지 일괄 정렬
Cross 페이지 간 구조 오류 자동 교차 검출
QA Loop 수정 → AI QA → 재검증 반복 품질 관리

주요 역할 및 업무

• 반응형 웹 퍼블리싱
모바일·태블릿·데스크톱 전 구간에서 자동으로 대응하는 유연한 레이아웃 구현

• 순차 전환 구조 설계
적응형 운영을 유지하면서 반응형 전환 페이지만 선별적으로 코드를 통합하는 파일 구조 및 분기 체계 설계

• SEO / AEO / GEO 마크업 강화
시맨틱 마크업, heading 계층 구조, AI를 이용한 스키마 작성 및 연결, meta 태그 정비를 통해 검색 노출 및 AI 인용률 개선

• 공통 컴포넌트 분리
페이지별로 중복 포함되어 있던 공통 요소를 별도 파일로 분리하고 구조를 재정비하여 유지보수 효율화
